# Matcher requirement profiles

Smart Document Intake now queues previews through Celery with durable PostgreSQL job state. The synchronous preview endpoint remains available for integrations and controlled tests. See the tracked [processing and deployment notes](../../../MATCHER_PROCESSING_PERFORMANCE.md), including the required job-table migration and the limits of the timing evidence. The older packet-profile discussion below describes the original synchronous request path.

This mode is experimental and **disabled by default** (`MATCHER_POLICY_PROFILES_ENABLED=false`). The October 12 same-sample Docker test regressed overall project Top-1 from 84/93 to 67/93 while fallback increased from 4 to 60 cases. Keep the existing Matcher prompt as the default. Enable this flag only for controlled evaluations; no increase in production accuracy or reduction in MOE has been established.

Evidence selection has its own independent flag, `MATCHER_EVIDENCE_SELECTION_ENABLED=true` by default. It selects an initial context segment and high-value identity/operative passages across the redacted document within the existing 1,800-character excerpt limit; it does not change candidate eligibility or project resolution. In a fresh 33-file automatic-discovery Docker benchmark on 2026-10-24, enabling evidence selection changed exact top suggestion from 22/33 to 23/33 (66.67% to 69.70%), held Top-3 at 28/33 (84.85%), and introduced no observed case-level regressions. This is a measured result on this cohort, not a population-accuracy estimate. Set the flag to `false` to restore prefix-only evidence. Profiles remain independently disabled by default. The 16-case prompt diagnostic measured 38.82% fewer prompt characters than its first experimental prompt on identical inputs; that is not a token or accuracy estimate.

`GROQ_SHARED_COOLDOWNS_ENABLED=true` shares cooldown TTLs through the configured Redis Celery broker. Atomic extension never shortens an existing TTL. Credential/model/endpoint hashes identify cooldown entries; no raw key is stored. A successful concurrent response does not erase shared cooldowns. Redis failure retains local failover. Cursors remain process-local; provider quotas are not replenished or globally scheduled by this mechanism. Web and worker processes must load matching code and updated environment variables; merely restarting an old container does not refresh its configured keys.

`matcher_requirement_profiles.json` supplies document-identity definitions and contrasts to the Matcher AI prompt. It contains 17 profiles and identifies the exact supplied Omnibus/SGLG-IF source copies with SHA-256 hashes and table/annex locations.

Profiles match descriptive requirement titles, not unqualified annex letters. They do not create requirements, determine mandatory applicability, change project checklists, or declare documentary compliance. Unknown titles retain the existing name/type/annex context. The authorized project's candidate IDs remain the response boundary.

`matcher_policy_service.py` loads and hashes the packaged catalog once per process. The AI response metadata records the catalog version/hash and evidence-selection ranges. The prompt includes candidate program, funding year, project kind and phase where available.

Evidence selection operates on already-redacted text. It selects an initial context segment and priority document titles/operative statements across the document within the existing 1,800-character excerpt limit. Offsets refer to redacted text. Page numbers are only available when explicit form-feed boundaries exist; ordinary flattened PDF/OCR text does not provide reliable page provenance. Empty OCR remains empty evidence and is not treated as proof of a document type.

Project discovery also recognizes the bounded title abbreviation `MPB` as `multipurpose building` for phrase-level review retrieval. This evidence does not add to project scores or resolve a project/phase. When a phrase matches a project family, the resolver can append up to three such projects to its ranked shortlist so the reviewer and requirement classifier can see them; unresolved status remains review-only.

Project-level `custom_fields` may also carry explicit `project_aliases`, `alternate_project_names`, `alternate_names`, or `aliases` string/list values. Exact distinctive aliases can append a project to the review shortlist, but never change its score or resolve it automatically. Free-form `Project.notes`, status fields, workflow comments, and generic project descriptions are excluded from identity matching. Do not copy benchmark labels or expected destinations into these alias fields; populate them only from independently verified source records.

LTO registration instruments can also retrieve vehicle projects for review from a named government owner/payer. This requires an LTO heading, registration/receipt evidence and vehicle fields; branch addresses, supplier rows and ordinary references do not qualify. It adds no score and does not establish unique project or asset identity. Responses expose `requirement_scope` to distinguish an empty upstream project scope, an empty active checklist, and type incompatibility within a populated scope. The AI receives explicit funding years separately from execution dates and vehicle model years; no funding year is inferred from those dates. These changes require a fresh full-cohort benchmark before claiming an overall accuracy gain.

Contractor billing is a separate identity/family from monitoring progress reports. An early disbursement voucher with an operative progress/final/contractor billing payment purpose can identify a billing packet even when a cheque is its first page. The payment-purpose passage is eligible for the existing bounded AI excerpt; supporting inspection/completion/photo attachments do not make the billing slot a progress-report/photo conflict. Ordinary billing references, salary vouchers and enclosure lists do not establish that identity.

The Docker packet profile accepts documentary files up to 80 MiB inside a 100 MiB request, processes up to 50 PDF pages, retains up to 200,000 extracted characters, and checks a 600-second processing budget between pages. A single in-progress page may finish after that budget; individual OCR calls remain bounded. Nginx/Gunicorn allow 900 seconds for long requests. Gunicorn defaults to two workers (`WEB_CONCURRENCY`) so one scan does not occupy its only worker. The profile is configured in both Compose files and the local/production environment files; non-Docker application fallbacks remain 25 MiB files, 32 MiB requests, five pages and 12,000 characters. PDF image OCR reuses its reader instead of reopening the whole file for each page. The AI excerpt stays at 1,800 characters, with selections and page offsets recorded. This is synchronous processing; queued OCR is a separate scaling improvement.

PDFs exceeding a page, retained-text or processing-time limit, or containing unreadable pages, carry explicit coverage metadata and require review even when their suggested match score is high. Unprocessed page numbers and per-page retained-character counts are reported. Heuristic score merging and numeric suggestion thresholds are unchanged. Photo understanding, calibrated confidence, multi-requirement bundle mapping and independent benchmark-label adjudication remain separate follow-up work. A trial consolidating likely duplicate test records is a catalog sensitivity experiment and must be disclosed separately from matcher-code improvements.

Both backend Dockerfiles copy the backend tree, including this catalog. The local Compose setup bind-mounts `backend` into web and worker containers. The web process reloads Python changes; worker processes need restarting to load changed modules. For image-based deployments, rebuild/recreate backend and workers together. Verify matching catalog hashes in each process. No extra runtime document library or network retrieval is required.

When editing profiles, retain source-qualified references, review semantic distinctions, bump the catalog version, restart processes to clear the catalog cache, and run the focused Matcher tests and an independent accuracy evaluation. Do not update frozen benchmark labels to match model predictions.
